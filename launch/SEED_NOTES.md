# SEED_NOTES.md — 시딩 리서치 방법론 및 한계 (2026-07-09)

## 방법론
- 5개 지역 병렬 웹 리서치(성수·한남 / 연남·합정 / 을지로·익선동·서촌 / 압구정·신사·양재 / 망원·해방촌 등)로 실제 운영 중인 서울 스페셜티 커피 로스터리 조사
- **네이버맵/카카오맵 데이터는 사용하지 않음** (CLAUDE.md §6 금지사항). 출처는 각 로스터리 공식 홈페이지·공식 인스타그램·신뢰 가능한 커피 전문 매체(블랙워터이슈, 디에디트, 바리스타뉴스, 에스콰이어 등)로 한정
- 자체 로스팅이 확인되지 않는 곳(타 로스터리 원두 편집숍, 해외 로스팅 후 국내 판매 등)은 제외 — "확신 없으면 제외" 원칙(추측 금지)
- 익선동은 조사 결과 자체 로스팅 스페셜티 카페를 확인하지 못해 리스트에서 제외 (한옥거리 특성상 디저트·베이커리 카페 위주)

## 정직하게 밝히는 한계
1. **영업 여부 미확인**: 모든 행의 `operating_status`는 "미확인"이다. 웹 검색은 최근 정보를 반영하지만 실시간 폐업/이전을 보증하지 못한다. LAUNCH_CHECKLIST Week 1의 "영업 여부 전수 확인"은 여전히 사람이 해야 하는 작업이다(방문·전화·최신 인스타 게시물 확인).
2. **원두 100~150종 목표 미달 (29종)**: 다수 로스터리의 공식 홈페이지가 자동 접근을 차단하고 있어(403), 검색 스니펫과 매체 인용만으로 컵노트를 확보했다. 원두명만 확인되고 공식 컵노트 원문을 못 찾은 곳은 아예 제외했다 — 이름만 채워 넣는 padding은 하지 않았다. 갭을 메우려면 로스터리별 공식 인스타그램을 직접 열람하거나(현재 세션 프록시 제약으로 다수 차단됨), 사람이 직접 방문/문의해야 한다.
3. **체인 브랜드의 로스팅 소재지**: 마일스톤·테일러커피·프릳츠·커피리브레처럼 여러 지점을 가진 브랜드는 중앙 로스팅 후 지점 배송인 경우가 많다. `is_roastery`는 "이 브랜드가 자체 로스팅한 원두를 파는가" 기준으로 true 처리했다 — "이 지점 안에서 물리적으로 로스팅하는가"와는 다르다. DB 시딩 시 이 구분이 중요하면 별도 컬럼 분리를 검토할 것.
4. **주소 정확도**: 일부(레드플랜트, 빌리프커피로스터스)는 행정동 표기가 검색 결과마다 달라 확신도를 낮게 표기했다. PostGIS 좌표 입력 전 재확인 권장.

## 앱 반영 (2026-07-12)
- `scripts/generate-seed.mjs`가 이 CSV들을 `lib/mock/seed.generated.ts`로 변환해 앱에 반영했다 (카페 49 + 원두 28). **데이터 수정은 CSV → 재생성** 순서로만 한다 — 생성 파일 직접 수정 금지.
- 신규 항목의 평점은 전부 null(체크인 0건) — 5건 룰을 실데이터에 그대로 적용. 소수 카페에만 시연용 집계 자리표시자를 얹었고(스크립트의 DEMO_AGGREGATES, 전부 가짜임을 명시), Supabase 집계 배치 연결 시 소멸한다.
- 좌표는 지역 중심 근사값만 저장 — 실좌표는 카카오맵 키가 있는 환경에서 공식 지오코더로 클라이언트 해석(크롤링 금지 원칙 준수).
- 원두는 CSV 데이터 행 기준 28종 전부 반영 (위 "29종" 표기는 재확인 결과 헤더 포함 계산 — 실데이터는 28행). 상품명이 일반명사인 "케냐 싱글오리진"(트래버틴)은 slug를 travertine-kenya로 구분 부여.

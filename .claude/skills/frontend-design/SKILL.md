# Frontend Design — 고유성 원칙

> 출처 고지: anthropics/skills의 frontend-design 원본을 이 세션에서 직접 가져올 수 없어(GitHub 접근 범위
> 제한 — cross-tier add 불가), 해당 스킬이 일반적으로 강조하는 것으로 알려진 원칙(제네릭 AI 룩 회피, 고유
> 시각 언어, 절제된 볼드함)을 이 프로젝트 DESIGN_DIRECTION.md에 맞춰 재구성했다. 원본 레포 확보 시 이 파일을
> 교체하고 DESIGN_DIRECTION.md와 대조해 차이를 기록한다.

## 핵심 원칙

1. **"어디서 본 것 같은" 느낌은 실패다.** 특히 다음 3종 AI-디폴트는 이 프로젝트에서 명시적으로 금지되어 있다
   (DESIGN_DIRECTION §1):
   - 크림 배경 + 테라코타 액센트
   - 검정 배경 + 형광 그린 단일 액센트
   - 신문형 hairline 레이아웃
   → 이걸 피하는 것만으로 부족하다. "우리만의 것"이 뭔지 매번 다시 확인해야 한다: 이 제품의 시그니처는
   ①히어로의 회전 원두 ②레이더 차트, 이 둘뿐이다. 나머지 화면에서 새로운 볼드함을 만들지 않는다.

2. **볼드함은 한 곳에 쓴다.** 모든 화면을 개성 있게 만들려는 유혹을 거부한다. 승인 게이트 화면(히어로/
   공유카드/`/c` 랜딩)만 아름다움의 기준이 높고, 나머지는 Ugly 허용(DESIGN_DIRECTION §5) — 이건 게으름이
   아니라 사용자의 주의를 어디로 쓸지 정하는 설계 결정이다.

3. **토큰 밖으로 나가지 않는다.** 임의의 색·폰트·radius를 그때그때 정하면 "고유한 디자인 시스템"이 아니라
   "일관성 없는 화면들의 모음"이 된다. 새 색이 필요하다고 느껴지면, 그건 보통 기존 토큰(roast-900/700,
   crema-100/400, amber-glow)의 투명도·배치를 바꿔서 해결된다.

4. **그림자 대신 보더+아우라.** 다크 테마에서 그림자는 시각적으로 죽는다(DESIGN_DIRECTION §2 형태 규칙).
   깊이는 보더 대비와 아우라 그라데이션으로 표현한다 — 이미 `bg-aura` 유틸리티와 카드 보더로 구현됨.

5. **모션은 목적이 있어야 브랜드가 된다.** 히어로의 14초 회전, 스크롤 페이드는 "화려해서"가 아니라
   "빠르면 싸 보인다"는 명시적 판단(DESIGN_DIRECTION §3)에서 나왔다. 새 모션을 추가할 때 같은 질문을
   던진다: 이게 없으면 뭐가 손해인가?

## 체크리스트 (새 화면/컴포넌트 만들 때)

- [ ] 이 화면이 승인 게이트 대상인가, Ugly 허용 대상인가 — 먼저 정하고 그에 맞는 노력을 쓴다
- [ ] 새로 쓰는 색/폰트/radius가 DESIGN_DIRECTION.md 토큰표에 있는가. 없으면 토큰표를 먼저 고친다
- [ ] AI-디폴트 3종(크림+테라코타, 검정+형광그린, 신문 hairline) 중 하나를 무의식적으로 반복하고 있지 않은가
- [ ] 이 화면에 이 제품만의 시그니처(회전 원두 / 레이더 차트)를 억지로 끼워넣고 있지 않은가 — 시그니처는
      두 곳으로 충분하다

## 이 프로젝트에서의 적용

ui-ux-max-pro(관례·사용성)와 충돌 시 이 스킬(고유성)이 우선한다(WORKFLOW.md §4.1) — 단, "고유하다"는
이유로 사용자가 못 알아보는 인터랙션을 만드는 건 고유성이 아니라 사고다. 승리한다는 건 관례를 무시해도
된다는 뜻이 아니라, 관례 위에 브랜드를 얹는다는 뜻이다.

# UI/UX 관례·품질 체크리스트

> 출처 고지: nextlevelbuilder/ui-ux-pro-max-skill 원본을 이 세션에서 직접 가져올 수 없어(GitHub 접근 범위 제한),
> 널리 합의된 사용성 휴리스틱(Nielsen 10원칙)과 모바일 폼팩터 관례를 이 프로젝트 맥락으로 재구성했다.
> 원본 레포 확보 시 이 파일을 교체한다.

## 역할

frontend-design이 "이 제품만의 고유한 시각 언어"를 담당한다면, 이 스킬은 "사용자가 실제로 헷갈리지 않는가"를
담당한다. 화면이 예뻐도 탭할 곳을 못 찾으면 실패다.

## 체크리스트 (화면 구현 시 매번)

**터치/입력**
- [ ] 터치 타깃 최소 44×44px (스타 반쪽 클릭, 태그 칩, 슬라이더 손잡이 포함)
- [ ] 320px 폭에서 잘리는 텍스트·버튼 없음 (DESIGN_DIRECTION §5 강제 규칙과 동일)
- [ ] 키보드 등장 시 입력 필드가 가려지지 않음 (메모 필드 제외 — 이건 CLAUDE.md에서 이미 예외)

**상태**
- [ ] 로딩/빈 상태/에러 상태 셋 다 디자인했는가 (다이어리 빈 상태는 이미 구현됨 — 이 패턴 유지)
- [ ] 폼 검증 실패 시 어디가 왜 틀렸는지 즉시 보이는가 (체크인 "기록 완료" 버튼 disabled보다,
      필수 항목이 뭔지 먼저 보여주는 방향 검토)
- [ ] 낙관적 UI가 필요한 곳(체크인 제출)과 확정 대기가 필요한 곳을 구분했는가

**흐름**
- [ ] 뒤로가기/이전 단계가 항상 있는가 (체크인 3스텝에 이미 있음)
- [ ] 한 화면에 주 행동(primary action)은 하나. 나머지는 시각적으로 종속시킨다
- [ ] 진행 표시(스텝 인디케이터)가 현재 위치와 전체 길이를 동시에 알려주는가

**관례 패턴 (재발명 금지 — 익숙한 걸 낯설게 만들면 마찰)**
- 스텝퍼: 상단 점/바 형태, 현재 단계 강조 + 완료 단계 구분
- 슬라이더: 손잡이 크기 44px 이상, 현재 값 숫자 병기 (FlavorSliders에 이미 적용)
- 칩/태그: 선택됨 상태가 색+보더 이중으로 구분되어야 함 (색약 접근성)
- 별점: 반쪽 단위는 탭 영역을 좌/우로 분리하는 게 슬라이더보다 마찰이 적음 (StarRating에 이미 적용)

**접근성**
- [ ] 대비: crema-100(#F1E7DB) on roast-950(#120C09) 등 토큰 조합은 AA 통과 확인됨. 새 조합 쓸 때 재확인
- [ ] 인터랙티브 요소에 aria-label (사진 미리보기, 별점 버튼 등)
- [ ] `prefers-reduced-motion` 존중 (히어로 3D에 이미 적용 — 다른 모션 추가 시도 동일 규칙)

## 이 프로젝트에서의 적용

frontend-design과 충돌하는 지점(예: "관례를 깨는 게 브랜드 정체성"이라는 주장)이 나오면 WORKFLOW.md §4.1의
우선순위대로 frontend-design(고유성)이 이긴다 — 단, 그 결정이 위 체크리스트의 "사용자가 헷갈리는가" 항목을
악화시키지 않는지는 반드시 확인하고 넘어간다.
